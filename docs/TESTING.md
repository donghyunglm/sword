# 검증 기록과 남은 확인

## 자동 검사

- `tests/test_combat.py`: 이동 속도, 피해 없는 대시, 경로 하나 유지, 대상당 1회 적중,
  단일/다중 적중 재충전, 만료, 얇은 벽, 프레임과 독립적인 경로 기록.
- `tests/test_game.py`: 15라운드 배치, 일시정지, 처치 목표, 강화와 재도전,
  저장 복원, 보상 중복 방지, 마지막 보스 이후 반복 방지, 손상 저장 보존, 체력 회복,
  F2 라운드 체험 중 기존 저장 유지.
- `tests/test_regressions.py`: 보스 방어/약점/재충전, 프리즘 1회 보상,
  멧돼지 예고 방향 고정, 대시 중 접촉 무적, 회피 후 잔영이 실제 약점에 닿는 시간 관계.
- `tools/verify_runtime.py`: 실제 pico2d 창에서 Enter, 방향키, Space, J, Esc 입력 처리와 종료.
- `tests/test_late_campaign.py`: 연결 단자 동시 타격, 탄환 제거, 새 보스 약점 제한, 성역 저장과 최대 강화 이후 진행.
- `tools/verify_playthrough.py`: 일반 게임의 이동·대시·참격·강화 선택만으로 1-1~3-5 클리어.
  진단용 저장은 `.cache` 안에 분리하며, 체력/피해/처치 목표를 우회하지 않는다.
- 숲·요새·성역·드래곤 장면은 실제 SDL 출력 버퍼를 PNG로 저장해 확인했다.

## 구현 중 수정한 문제

- 수호수의 돌진이 플레이어가 있던 위치를 너무 멀리 지나쳐 잔영 반격이 빗나가는 문제:
  예고 순간의 거리로 돌진 거리를 제한하고, 목적지 약 20px 뒤에서 회복하도록 변경했다.
- 강화 화면 후 낮은 체력이 계속 누적되는 부담: 라운드 전환 시 체력을 완전히 회복한다.
- pico2d 기본 이벤트 변환이 창 포커스 이벤트를 전달하지 않는 점:
  SDL 창의 포커스 상태를 직접 확인하고 자동으로 일시정지한다.

## 직접 플레이하며 추가로 볼 부분

- 키보드 종류와 개인의 반응 속도에 따른 대시·J 입력감.
- 일반 적을 모으는 시간이 지루하지 않은지, 1.2초의 잔영 유지가 적절한지.
- 선택 강화별 난이도 차이. 봇은 범위 강화를 우선하며 다른 조합의 재미를 보증하지 않는다.
- 최종 스프라이트의 크기·애니메이션 시점과 실제 판정 일치.
- 이 PC 외의 운영체제·Python·오디오 장치에서의 실행.

임시 2D 도형과 합성 효과음은 최종 자산이 아니다. 봇 완주는 실제 사람의 조작감·재미 검증을 대신하지 않는다.
